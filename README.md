# AB Explorer

VS Code 原生资源管理器的替代品：横向标签导航 + 层级树，专治「目录多到刷屏、
标签长到看不清、翻了三层才找到文件」。

## 安装

尚未上架 VS Code Marketplace，从源码本地打包安装：

```bash
git clone https://github.com/yinrong/ab-explorer.git
cd ab-explorer
npm install
npm run build
npx vsce package
code --install-extension ab-explorer-0.1.0.vsix
```

装好后重启一次 VS Code，活动栏左侧会出现 AB Explorer 的独立图标。

## 卖点

### 双区导航：A 区选目录，B 区看内容

上面 A 区是一排横向标签，代表当前层级下的子目录；点一下就切换到那个目录，
下面 B 区展示它的完整层级树。目录不深的时候（B 区不用滚动）A 区只有一行，
专注浏览子树；目录一深、B 区出现滚动条，A 区自动补一行标签把当前路径摊开，
不用来回滚动找自己在哪一层。

### 长目录名不再刷屏

`typhur-app`、`typhur-web`、`typhur-api` 这种同前缀目录，只保留第一个显示全名，
其余压缩成 `-app`、`-web`（悬停仍能看到全名）。前缀会被完整清除干净——不管
是 `3d-man1` / `3d-man1-agent1` 这种两三层嵌套，还是 `ai` / `ai-growth-plan` /
`ai-growth-plan-1` 这种递进式命名，都能算出最短、最不重复的差异部分；只是碰巧
共享一小段前缀的旁支目录（比如 `3d-man1` 和 `3d-man2`）不会被误判成一组。
一组标签数够多时，还会用一圈细边框整体框起来，一眼看出「这是一拨相关的」。

### 常去的目录自己会「亮」出来

A 区标签按点击频率自动着色，越常去的颜色越深，全程只用一个色系，不会和
别的视觉标记互相抢注意力。找那个天天开的项目目录，不用再从一排等宽白板
标签里一个个认名字。

### git 有改动的目录也不用挨个点开确认

某个子目录本身是一个 git 仓库、且有未提交改动时，名字前会点一个不起眼的
灰色小圆点。提交干净之后圆点自动消失，不需要手动刷新。

### 基础文件操作、右键就有

新建文件/文件夹、重命名、删除（进系统回收站，不是硬删）、在系统文件管理器
中显示、复制路径——不管是右键 A 区的标签还是 B 区树里的行，菜单都一致。
外部改了文件（比如用别的编辑器另存了一份），视图跟着自动刷新。

### 视觉功能嫌乱可以关掉

顶部有三个开关，分别控制「分组边框」「频率着色」「git 改动图标」这三项
附加的视觉效果，按需开关，选择会记住。基础的双区导航、标签压缩、右键操作
不受这三个开关影响，一直可用。

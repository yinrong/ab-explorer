# AB Explorer 核心需求

来源：[../10-原始需求/2026-09-13-ab-explorer.md](../10-原始需求/2026-09-13-ab-explorer.md)、
[../10-原始需求/2026-09-17-可用性增强.md](../10-原始需求/2026-09-17-可用性增强.md)

## 核心故事

替代 VS Code 原生资源管理器的双区视图：A 区横向标签导航目录层级，B 区显示层级树；
根据 B 区能否无滚动条完整显示，在"标签导航"（模式1）和"逐级下钻"（模式2）之间自动切换。

## 不让步的

1. **A 区标签前缀压缩**：同前缀子目录，非首个只显示 `-差异部分`，`title` 保留全名。
2. **模式判定纯看 B 区是否需要滚动条**，不是看深度、不是看用户手动切换。
3. **模式2 下溢出触发新增 A 区行时，自动选中导致溢出的目录**（用户刚展开的那个），不是选第一个。
4. **B 区默认折叠**，不默认展开。
5. **独立活动栏图标**承载本视图，不占用/替换原生资源管理器面板。
6. **基础文件操作**：打开、新建文件/文件夹、重命名、删除（进回收站）、在系统中显示、复制路径；
   外部文件变化自动刷新视图。
7. 从零实现（市场无现成插件满足此形状），TypeScript + VS Code Extension API。
8. **前缀压缩要把完整公共前缀清干净**（不能只砍掉前缀内部的第一个分隔符），
   且不能因为链上某个深层子目录跟旁支只共享一小段泛化前缀就把旁支错误并组；
   同一组标签数 ≥3 时用细边框整体框起来，不引入新颜色，且**边框必须自己换行**
   （`flex-wrap`），不能指望外层容器把整个框当成不可切分的一整块来换行——
   否则组内标签一多（几十个），框会整体溢出侧边栏宽度，看不全也不会自动折行。
   **组内差异部分如果还整体共享一段字母+纯数字的尾巴**（如 `agent1` `agent10`
   `agent11`），达到 3 个以上时进一步只留第一个显示完整文字、其余只显示数字，
   不然几十个标签会把 "agent" 这几个字重复几十遍，白占空间。
   **排序按数值感知**（`localeCompare(..., {numeric:true})`），`agent2` 排在
   `agent10` 前面，不按字符逐位比较——否则数字尾巴压缩完的显示顺序会是乱的。
9. **A 区标签按访问频率着色**：只用一个色系（蓝，`--vscode-charts-blue`）改变浓淡，
   不引入第二种颜色；从未访问强度为 0。频率不只算在这个插件里的点击次数，
   还要把「最近 14 天内这个目录作为 git 仓库根有多少次提交」一起算进去——
   很多改动是 AI/CLI 在 VS Code 外部直接改代码、跑 git commit 产生的，
   只看插件内点击次数会让常被打理的目录反而显示成"从没访问过"。
10. **A 区目录标签也要有右键菜单**（与 B 区一致：新建文件/文件夹、重命名、删除、
    在文件资源管理器中显示、复制路径）。
11. **目录本身是 git 仓库且有未提交改动时，名字前加一个图标**——用 VS Code
    自己「源代码管理」活动栏同款的分支图标（`codicon-source-control`）和
    git 语义色（`--vscode-gitDecoration-modifiedResourceForeground`），
    不用一个普通圆点（不够醒目、容易被当成装饰）；
    不做「目录内部文件有改动」的递归脏标记（只判目录自身是不是脏仓库根）。
12. **顶部 toggle 开关只控制视觉类附加功能**（分组框、频率着色、git 改动图标），
    默认全开，按 workspace 持久化；右键菜单属于基础交互能力，不受开关影响。
13. **编辑器切换活动文件时自动定位**（对应 VS Code 原生资源管理器的 Auto
    Reveal）：目标文件已经在当前 B 区子树下就不改 path，只展开祖先目录并高亮
    该文件行；不在的话把 path 收回工作区根，需要的话按现有溢出检测一次性下钻
    到该文件所在目录。高亮用 `--vscode-list-inactiveSelectionBackground`（跟随
    原生资源管理器的语义色，不是 A 区标签那种强选中色）。可通过
    `abExplorer.autoReveal` 配置项关闭，默认开启。这不算"访问"，不计入
    频率着色的热度统计（那是主动点击/git 提交的信号，自动同步是被动的）。
